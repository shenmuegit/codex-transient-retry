# 实现原理

## 请求路径与配置

`configure()` 在 Codex 配置中加入有起止标记的管理块，将 `openai_base_url` 指向 `http://127.0.0.1:18761/backend-api/codex`。保留内置 `openai` provider，不再选择自定义重试 provider，以满足 Dot 对原生 OpenAI 身份的检查。原有 provider 行及用户配置保持原状；从旧自定义 provider 迁移时恢复原始 provider 行并移除旧管理块。

Codex 负责登录及生成鉴权头，代理不读取登录文件或创建 API key。业务请求统一转发到 `https://chatgpt.com`，保留路径、查询和正文；绝对形式的请求目标取其路径及查询。出站连接继续使用 urllib 的环境／系统代理设置及标准 HTTPS 证书验证。

业务入口不设置路径、HTTP 方法、鉴权、Origin、大小、超时或错误码访问策略。模型列表没有缓存或专属处理。`GET /health` 提供本机运行状态；带 `X-Codex-Retry-Control: stop` 的 `POST /shutdown` 是安装脚本的进程控制命令，其他 `/shutdown` 请求正常转发。

`openai_base_url` 只改变模型 provider 的连接地址，不自动接管桌面登录、更新或第三方插件的独立连接。

## 正文保留与协议解析

普通 HTTP 请求先读取完整正文以便重放。`Content-Length` 指定正文边界；分块上传按 chunk 大小读取，解码后的正文重放为带内容长度的请求，trailer 字段转为请求头。无效长度或分块语法无法形成完整请求，会返回 HTTP 400；这不用于限制合法正文的大小。

业务正文及内容编码保持不变。`Accept-Encoding` 直接转发，gzip 响应不再为客户端解压；重试判断在副本上按声明逆序解码 gzip／deflate（包括 raw deflate）并检查，返回时仍使用原始压缩字节和编码头。未知编码保持透传，HTTP 错误状态仍正常重试。HTTP 逐跳连接头及正文长度由各段连接处理，不能把两段 HTTP 连接描述为逐字节 TCP 复制。`HEAD` 保留上游内容长度，不发送正文。

上游重定向的状态、正文及 `Location` 返回客户端，由客户端决定后续请求；代理不将重定向改写为本地错误，也不自行替客户端访问重定向目标。

## 缓冲与统一重试

`fetch()` 完整接收 HTTP 响应；`retry_reason()` 只决定是否重试，不决定业务请求是否获准。所有路径和 HTTP 方法使用相同判断：

| 情况 | 行为 |
| --- | --- |
| HTTP 状态大于等于 400 | 重试，不按状态枚举或错误码名单排除 |
| JSON `error`、SSE `error`／`response.failed` | 重试，包括未知错误码 |
| 连接错误、正文读取中断、损坏的 gzip／JSON／UTF-8、模型事件缺少结束标记 | 重试 |
| 正常二进制、文本、JSON 数组、空响应及一般 SSE 文本 | 返回原始响应 |
| 模型 `response.incomplete` | 返回上游终止结果，不重新执行已完成的模型请求 |
| 客户端取消 | 在尝试边界和退避间隔停止 |

SSE 检查支持初始 UTF-8 BOM、CR／LF／CRLF、独立 `event:` 名及 `[DONE]`；没有 `Content-Type` 但正文具有 SSE 前缀时也能识别。错误码只用于日志分类，不是白名单或黑名单。JSON 的 `error: false`、0、空字符串、空列表和 null 不作为失败信号；明确的错误对象仍会重试。解释器因 JSON 嵌套或整数长度无法解析成功响应时，保留原始结果，不将解析器异常改写为 HTTP 502。

每次进入代理的 HTTP 请求最多尝试 4 次，即首次请求加 3 次重试，等待 30、60、120 秒。有效的 `Retry-After` 秒数或 HTTP 日期可以延长等待，没有额外的调度总时限。重试耗尽后返回最后一次上游状态、响应头及正文，不再生成 `local_retry_limit_exceeded` 或改写成 HTTP 400。连接故障没有完整上游响应时，返回描述连接故障的 HTTP 502。

客户端原生请求及流重试仍然启用，代理耗尽后可能再次收到客户端请求，因此 4 次不是全链路尝试上限。内置 `openai` ID 不能通过 `[model_providers.openai]` 重新定义来关闭原生重试。Dot 云端主会话不经过这个本机模型网关。

失败尝试中的文字和本机工具调用不会提前交给客户端。缓冲不能回滚服务端已经执行的工具；图片及其他写入操作可能在响应丢失前已经完成，重试可能重复执行或计费。保留调用方原有幂等键，不自行生成或修改。

## 升级连接

所有路径上的 HTTP Upgrade 都正常转发。握手失败使用同一重试循环；收到 HTTP 101 后把状态及升级头交给客户端，再以两个方向的字节复制维持连接。转发使用已有的读取缓冲，保留与握手一同到达的帧。

升级后的流量直接转发，不解析 WebSocket 帧，也不能在已经交付字节后透明重放。WebSocket 消息内的模型错误由客户端处理；代理的完整响应缓冲重试仅适用于普通 HTTP／SSE 及升级握手。

## 时长、资源与恢复

代理不附加请求／响应字节上限、I/O 超时、重试调度时限、并发配额或总内存配额。请求和响应保存在内存，大正文及并发请求会增加占用；静默连接可能持续等待。取消检查不能打断正在阻塞的上游读取。客户端、上游、HTTP 标准库及操作系统仍有各自的协议和资源边界。

安装器会将原配置及升级前配置备份到项目运行目录，验证管理块及并发修改后直接更新 Codex 配置，写入异常时尝试恢复原内容。直接更新避免在配置目录创建暂存文件；进程被终止或断电时可用项目中的备份恢复。修订 12 读取旧回滚状态，恢复原生 provider 身份并移除自定义 provider 块；重复启用保持幂等。关闭时移除管理块，保留其他用户配置。

元数据日志不记录凭据、查询参数、请求正文或响应正文。日志轮换只影响诊断记录的保留，不影响业务请求。监听地址仍为本机回环，回环 HTTP 不提供传输加密。配置备份及登录状态应保留在本机。重复请求头从入口到出站保留每个值，重试重放相同头和正文。
